## 2. Architecture
Static SPA (`dist/`) talking directly to Supabase with the **publishable (anon) key**. All privileged operations happen in Postgres (RLS + `security definer` RPCs) or Supabase Edge Functions (service role key stays in Supabase secrets only).

```
Browser (React SPA, Cloudflare)  ──►  Supabase REST/RPC (RLS)         [reads, owner/staff writes]
                                 ──►  Supabase Edge Functions         [public writes, admin user mgmt]
Supabase Postgres  ◄── pg_cron (rollups, plan expiry, cleanup)
```
Public writes (review, inquiry, suggestion/claim/report/new business, event tracking) go **only** through Edge Functions (validation, honeypot, rate limit via `check_rate_limit`). Anonymous users have **no direct INSERT** on those tables.

## 4. Supabase Integration Strategy
- `src/lib/supabase.ts` creates ONE client from `import.meta.env.VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. If not configured, export `supabaseConfig.isConfigured = false` and show a friendly "Database not configured" state — the app must still build and render.
- **No keys hardcoded** anywhere. `.env` is git-ignored; only `.env.example` (with empty values) is committed.
- `src/lib/api.ts` is the single data layer: every call uses the **exact table/column/RPC names from `05_Backend_Schema.md`**. Typed with `src/types/database.ts`.
- Public reads use RPCs `search_businesses`, `get_business_public`, `related_businesses` and table selects on public-readable tables.
- Public writes call Edge Functions with `supabase.functions.invoke('<name>', { body })`.
- Dashboards use RPCs `admin_dashboard_counts`, `admin_analytics`, `owner_dashboard_stats`.

## 5. Authentication & Authorization
- Supabase Auth email + password. Session persisted. `AuthProvider` exposes `user`, `profile` (from `profiles`), `signIn`, `signOut`, `refreshProfile`.
- `RequireAuth` (any logged-in user) and `RequireRole allowedRoles=[…]` guard routes; `must_change_password` forces redirect to `/change-password`.
- `usePermissions()` calls RPC `my_permissions()` → `{ role, is_active, staff_types, permissions[] }`; UI hides tabs/buttons by permission, **but RLS is the real enforcement**.
- Password reset: `supabase.auth.resetPasswordForEmail(email, { redirectTo: VITE_SITE_URL + '/reset-password' })`.
- User creation/reset/deactivation only through Edge Functions `admin-create-user`, `admin-reset-password`, `admin-set-user-active` (they verify the caller is super_admin or has `owners.create`).

## 6. Storage Strategy
No Supabase Storage buckets in v2. All images (logo, cover, gallery, owner photo, offer, ads) are **HTTPS URLs** (from PhotoToURL or similar). Validate with `^https://\S+$` and ≤ 500 chars on client and DB. `ImageWithFallback` handles broken URLs and offers "Report broken image" (→ `submissions` type `broken_image`).

## 7. Security Requirements
1. RLS enabled on all tables (see 05). Anonymous: read published/public data only.
2. Service-role key and any secret **never** in frontend, repo or `VITE_*` variables.
3. Column protection trigger prevents owners changing `status` (except draft/rejected→pending_approval), plan, verified/featured flags, counters, `owner_id`.
4. Edge Functions: validate input, honeypot field `website_hp` must be empty, rate-limit by `check_rate_limit(key, limit, window)`, CORS allow-list from secret `ALLOWED_ORIGINS`, **JWT verification OFF** for the public four (`submit-review`, `submit-inquiry`, `submit-suggestion`, `track-event`); **JWT verification ON** for admin functions and they re-check role in code.
5. Sanitize/escape all user text; render markdown pages with a safe renderer (no raw HTML).
6. Cloudflare `_headers` CSP: `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com data:; img-src 'self' https: data: blob:; frame-src 'self' https://www.youtube-nocookie.com https://player.vimeo.com; connect-src 'self' https://*.supabase.co wss://*.supabase.co https://*.tile.openstreetmap.org; worker-src 'self' blob:` plus `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=(self)`. (Do not use a blanket `https:` in connect-src.)

## 8. PWA & Offline
`manifest.webmanifest` (name, icons, theme color, `display: standalone`), `sw.js` precaches app shell + `offline.html`; emergency contacts cached in `localStorage` via `offlineStorage.ts` and shown offline. `PwaUpdateToast` prompts to refresh on new version. Service worker must never cache Supabase API responses other than emergency contacts.

## 9. Internationalization
`i18n.tsx` provides `I18nProvider`, `useI18n()` → `{ lang, isUrdu, t, setLang, urduHints, setUrduHints }`; sets `document.documentElement.lang` and `dir`. Dictionary keys for all UI strings in both languages. `Bi` component renders `English` plus a small Urdu gloss when `lang==='en' && urduHints`. Fonts: Plus Jakarta Sans (English) and Noto Nastaliq Urdu (line-height ≈ 2.1) via Google Fonts with fallbacks.

## 10. SEO
`seo.ts` sets `document.title`, meta description, canonical, Open Graph and injects JSON-LD (`LocalBusiness`) on business pages. `robots.txt` allows all except `/admin`, `/owner`. Sitemap generated from Admin → Backup & Export and placed in `public/sitemap.xml`.

## 11. Cloudflare Deployment Requirements
- Platform: Cloudflare **Workers & Pages**, connected to the GitHub repo (main branch auto-deploy).
- Build command `npm run build`; output directory `dist`; Node 20+.
- SPA fallback: `public/_redirects` containing `/*    /index.html   200`. Do **not** add a top-level `404.html`.
- `public/_headers` as in section 7.
- Lock files: only `package-lock.json`; `.npmrc` with `legacy-peer-deps=true` in root.
- No `vercel.json`, no Express server.

## 13. Performance
Route-level `React.lazy`, image `loading="lazy"` + `width/height` or aspect-ratio boxes, debounce search (300 ms), paginate lists (20 per page), avoid heavy chart libraries (use light SVG charts), memoize list items, skeleton loaders.

## 14. Testing / Quality
`npm run lint` (tsc) must pass; `npm run build` must pass with zero errors. Manual QA checklist in `06_Implementation_Plan.md`. RLS test SQL files are part of the schema deliverables (see 05).
