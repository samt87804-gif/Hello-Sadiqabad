## 1. Purpose & Goals
Hello Sadiqabad is a **mobile-first city phone book and business directory exclusively for Sadiqabad, District Rahim Yar Khan, Punjab, Pakistan.** It is informational only: **no payments, no money handling, no checkout.**

Goals:
1. Let any resident find a phone number, address, hours, map location or offer for a local business in under 10 seconds, in English or Urdu.
2. Give business owners a real self-service portal (v1 only had a placeholder).
3. Give the admin team a complete back-office: data entry, bulk import, moderation, sales leads, ads, analytics and audit.
4. Work well on cheap Android phones and slow networks (PWA, code-splitting, offline emergency numbers).

Success metrics: search-to-call time, monthly active searchers, % listings with phone + category + area + image, owners activated, review moderation turnaround.

## 2. Target Users
| User | Description |
|---|---|
| Visitor (anonymous) | Resident searching for a business, doctor, shop, service or emergency number. No login needed. |
| Business owner (`owner`) | Owns one or more listings; logs in with an account created by staff (or approved claim). |
| Staff (`staff`) | Team member with one or more `staff_types` giving limited permissions. |
| Super admin (`super_admin`) | Full control of everything. |

## 3. Languages (IMPORTANT REQUIREMENT)
- Two full languages: **English (`en`, LTR)** and **Urdu (`ur`, RTL, Noto Nastaliq Urdu)**. A visible language switch is in the header on every page, and instantly flips text and direction without reload. Choice is saved (`hs_lang`).
- **Urdu Hints in English mode:** when the site is in English, key words (navigation, buttons such as Call / WhatsApp / Directions / Search / Emergency, section titles, plan names) also show a **small Urdu gloss** next to the English text so Urdu-only readers are not confused. Example: `Call · کال کریں`. A toggle "Show Urdu hints" (default ON, key `hs_urdu_hints`) is in the language menu. Hints are not shown in Urdu mode (already Urdu).
- Business data is bilingual (`name_en/name_ur`, `description_en/description_ur`, `address_en/address_ur`). If the Urdu value is missing, show English (and vice versa) — never an empty field.
- Search understands English, Urdu script and **Roman Urdu** (e.g. "dawai", "hospital", "doctar", "nai", "bijli") through category synonyms and business tags.

## 4. Features

### 4.1 Public directory (all carried from v1, improved)
1. **Home:** hero search, quick-search links (Hospital, Doctor, Police…), popular categories, current offers, announcements ticker, recently added listings, featured/sponsored ads, "Add your business" call to action.
2. **Search:** text search + filters (category, area, **Open now**, verified, has offer, min rating, home delivery) + sort (relevance, rating, nearest, newest). Plan priority boosts ranking (premium > basic > free). Autocomplete suggestions. Pagination (infinite scroll "Load more").
3. **Categories** page (tree: parent → sub-categories) and **Category detail** page (`/category/:slug`).
4. **Area pages** (`/area/:slug`) — all businesses in a neighbourhood (new).
5. **Business profile** (`/business/:slug`): name, category, area, verified badge, rating, Open/Closed now, one-tap **Call**, **WhatsApp**, **Directions** (Google Maps link), **Share**, **Save (favorite)**, **QR code**, photo gallery (lightbox), videos (YouTube/Vimeo embeds), opening hours table, social links, description, services list, offers, reviews (approved only), **Send Inquiry**, **Write Review**, **Suggest Correction / Report**, related businesses. JSON-LD `LocalBusiness` structured data and per-page `<title>`/meta.
6. **Offers** page: active, in-date offers from businesses.
7. **Map** page: Leaflet + OpenStreetMap, markers for published businesses with coordinates, filter by category, "near me" (geolocation, optional).
8. **Favorites** page: saved businesses (stored on device, key `hs_favorites`; no login needed). **Recently viewed** list on device (`hs_recent`).
9. **Emergency** page: 1122 Rescue, 15 Police, 16 (Fire), 115 Edhi/Ambulance plus hospitals/utilities from `emergency_contacts`; cached for **offline** use; tap to call.
10. **Announcements** page (`/announcements`) (new): city notices posted by admin (e.g., closures, events).
11. **Add Business** (public form → `submissions` type `new_business`, goes to moderation).
12. **Static pages** (markdown from DB): about, advertise, contact, terms, privacy, listing-terms, refund-policy, faq.
13. **PWA:** installable, offline fallback page, update toast.
14. **Dark mode** (system default + manual toggle, key `hs_theme`).

### 4.2 Authentication
- Email + password login (`/login`). Accounts for owners and staff are **created by admin** (Edge Function) with `must_change_password = true` → forced to `/change-password`.
- **Forgot password** (`/forgot-password` → email link → `/reset-password`) using Supabase Auth (new).
- Admin can reset a user's password and activate/deactivate users.
- Public visitors never need an account.

### 4.3 Business Owner Portal (`/owner/*`) — fully built in v2
| Page | Capabilities |
|---|---|
| `/owner` Dashboard | My listings, plan + expiry, stats (views/calls/WhatsApp/directions last 7/30 days), new inquiries/reviews count, notifications |
| `/owner/listings/:id` Listing editor | Edit all allowed fields (bilingual text, phones, hours editor, location pin picker, social links, gallery/video **URLs** within plan limits, services, tags, home delivery, 24/7), live preview, "submit for approval" (status → `pending_approval`) |
| `/owner/offers` | Create/pause/delete offers within plan limit, with image URL and validity dates |
| `/owner/reviews` | See approved reviews, **reply** once per review |
| `/owner/inquiries` | Inbox of inquiries; mark read/handled |
| `/owner/analytics` | Day-by-day chart of views/calls/WhatsApp/directions/share, top search terms hitting the listing |
| `/owner/plan` | Current plan features vs other plans, **Request upgrade** (creates `submissions` type `plan_upgrade`; sales contacts them; no payment in app) |
| `/owner/profile` | Name, phone, change password |
| `/owner/notifications` | In-app notifications list |
| Claim a listing | Anyone can submit a **claim** from a business page (`submissions` type `claim`); staff verify and link `owner_id` |

Owners **cannot** change: `status` (except submit for approval), `plan_code`, `plan_expires_at`, `is_verified`, `is_featured`, counters, `owner_id` (enforced by DB trigger).

### 4.4 Admin & Staff Panel (`/admin`)
Tabs (permission-gated): **Overview, Businesses, Moderation, Inquiries, Sales Leads, Owner Accounts, Batch Import, Ads & Banners, Listing Tiers, Categories & Areas, Announcements, Team & Roles, Analytics, Data Quality, Backup & Export, Site Settings, Audit Logs.**

Advanced admin features (new in v2):
1. **Dashboard** with counts and charts (pending items, new listings, top searches, searches with zero results).
2. **Bulk actions** on businesses: publish, archive, change category/area, assign to staff.
3. **Duplicate detection** by normalized phone number and similar names, when adding/importing and via a "Find duplicates" tool.
4. **CSV/Excel import** with column mapping, validation preview, per-row errors and an import history.
5. **Data Quality report:** listings missing phone/category/area/image/coordinates/Urdu name; broken-image reports; export the list.
6. **Plan expiry board:** plans expiring in 7/30 days and expired (auto-downgrade to free via scheduled job).
7. **Ads manager:** placements, dates, status, impressions/clicks and CTR.
8. **Sales pipeline** (leads: new → contacted → interested → paid → converted / dropped / not_interested) with notes and assignment; convert lead → listing + owner account.
9. **Internal notes** on any business.
10. **Announcements** with start/end dates, language versions, optional link.
11. **Static page editor** (markdown, both languages) and **site settings** editor.
12. **Backup & Export:** CSV/JSON export of businesses, categories, areas, leads; sitemap.xml generator for upload to `public/`.
13. **Audit log** of every sensitive action (who, what, when).
14. **Global admin search** across businesses, leads, owners.

### 4.5 Roles & Permissions
Roles: `super_admin`, `staff`, `owner`. Staff types and their permissions:

| staff_type | Permissions |
|---|---|
| data_entry | business.create, business.edit_own |
| importer | import.run, business.create |
| sales_onboarding | leads.manage, owners.create |
| listing_manager | tiers.manage, ads.review, business.create, business.edit_own, business.publish, analytics.view |
| moderator | business.publish, moderation.review, ads.review |
| support | support.read, moderation.review |
| (any, via custom override) | announcements.manage, analytics.view, settings.manage can be granted individually in `staff_members.permissions` |

`super_admin` has all permissions. Inactive staff lose all permissions immediately. A staff member may belong to multiple types.

## 6. Business Rules
1. Only `status = 'published'` businesses are public. Status flow: `draft → pending_approval → published`; admin may set `rejected`, `suspended`, `archived`.
2. Reviews are public only when `approved`; anonymous users can submit reviews (name + rating + comment) which start as `pending`. Rate-limited and honeypot-protected.
3. Rating (`rating_avg`, `rating_count`) is computed only from approved reviews.
4. Phone numbers are normalized to Pakistani format (`03xx-xxxxxxx` / E.164 `+92…`) in `phone_normalized` for duplicate detection and search.
5. All external URLs (website, social, images, ads) must be `https://` and ≤ 500 characters.
6. Plan limits are enforced in both UI and database (owner cannot exceed gallery/video/offer limits).
7. No personal data of visitors is stored in analytics: only random `session_id`, no IP.
8. Everything is scoped to a city (`city_id`) so another city could be added later, but v2 launches with **Sadiqabad only** (`VITE_DEFAULT_CITY=sadiqabad`).

## 7. Non-Functional Requirements
- Mobile-first (design for 360×640), touch targets ≥ 44px, Lighthouse mobile performance ≥ 85, initial JS bundle small via route-level code-splitting.
- Accessibility: WCAG AA contrast, keyboard navigation, `aria` labels, `lang`/`dir` set correctly, visible focus.
- Security: RLS on **every** table, no service-role key in frontend/repo, input validation client + server, rate limits on public writes, CSP headers.
- Reliability: graceful loading/empty/error states everywhere; global error boundary.
- SEO: per-page title/meta, Open Graph, JSON-LD, `robots.txt`, sitemap.
- Offline: emergency numbers + app shell available offline.

## 8. Scope
**In scope:** everything above. **Out of scope (v2):** online payments, user-generated photo upload to Supabase Storage (images are pasted URLs from PhotoToURL), AI chatbot/AI features (so **no Cloudflare AI Gateway** is required), native mobile apps, multi-city launch, SMS/WhatsApp API sending, public user accounts.
